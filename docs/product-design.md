# AI 简历助手 — 产品设计文档 v1.0

> 定稿日期：2026-04-09
> 状态：已定稿，可进入技术方案阶段

## 一、产品定位

面向 C 端求职者的 AI 简历助手。用户通过自然对话构建和优化简历，AI 以 ReAct Agent 方式实时修改简历内容，支持针对不同职位 JD 的定向优化。

**目标用户**：25-35 岁，有一定工作经验的求职者，或需要优化简历的应届生。

**核心差异化**：
- 对话式交互，不是表单填写
- AI 有长期记忆，记住用户背景，跨简历生效
- 支持 JD 匹配分析和针对性优化

**推广渠道**：小红书为主，积分制低门槛体验（注册送 100 积分）

## 二、数据模型（业务层）

```
User（用户）
 ├── 长期记忆 memory_facts       ← 跨所有简历共享，AI 记住你的背景
 ├── Token 用量 token_usage      ← 每次 LLM 调用记录，用于成本核算
 ├── 积分账户 user_credits       ← 余额快照
 ├── 积分流水 credit_transactions← append-only，永不删除
 └── Resume（简历）1:N
      ├── JSON 数据（单一数据源）
      ├── 模板 ID + 模板标签
      ├── 标题（用户在创建时手动命名）
      ├── 来源标记（新建 / 复制自某份简历）
      └── Session（对话线程）1:1
           ├── Messages（消息列表）
           └── conversation_summaries（压缩摘要）
```

**核心设计原则**：
- Resume 和 Session 分表存储，Resume 是资产，Session 是历史
- 业务上 1:1 强约束，架构上为 1:N 预留扩展口
- 简历数据属于 Resume，多个操作（JD 优化、上传解析）都修改同一份数据
- 复制简历 = 数据快照 + 全新空 Session，两份简历此后独立迭代
- 长期记忆属于 User，Agent 跨简历可感知用户背景

## 四、页面设计

### 4.1 Dashboard（/dashboard）

**布局**：顶部导航栏 + 简历卡片网格（4列）

**导航栏**：
- 左：产品 Logo
- 右：积分余额 chip（点击打开充值弹窗）+ 用户头像（点击展开：账号设置 / 退出登录）

**简历卡片**：
- 显示：模板缩略图 + 简历名称 + 最后编辑时间 + 模板标签
- Hover 状态：显示三个图标按钮：✏️ 改名 / ⎘ 复制 / 🗑 删除
- 点击卡片主体：进入编辑器

**空状态**：无简历时展示引导插画 + "创建你的第一份简历" CTA

**操作**：
- 「+ 新建简历」按钮 → 打开新建简历弹窗
- 改名：inline 编辑，点击确认保存
- 删除：弹出二次确认弹窗，提示「删除后不可恢复，包括所有对话记录」
- 复制：立即创建副本，跳转到新简历编辑器

---

### 4.2 新建简历弹窗

**触发**：Dashboard「+ 新建简历」按钮 / 编辑器左侧「+ 新建简历」按钮

**弹窗结构（从上到下）**：

1. **简历名称输入框**（必填）
   - placeholder：「例：后端工程师 · 2026」
   - 创建后用户可在编辑器里随时改名

2. **模板选择区**（左侧，主区域）
   - 标签筛选条：全部 / 简约 / 现代 / 商务 / 校招 / 外企 / 技术岗 / 英文
   - 模板卡片网格（3列），每张卡片显示缩略图 + 名称 + 标签
   - 模板列表（初版 6 个）：经典、现代双栏、极简、商务、校招版、创意
   - 说明文字：「进入编辑器后仍可切换」

3. **起点选择**（右侧）
   - 从头开始：和 AI 对话构建
   - 上传已有简历：选择 PDF/DOCX 文件，AI 解析后填充

4. **底部操作栏**：取消 / 开始创建

**选「上传已有简历」时的处理**：
- 弹窗关闭，进入编辑器
- 右侧出现文件选择器
- 上传完成后 Agent 自动处理（见 4.3 上传冲突逻辑）

---

### 4.3 编辑器（/resume/:id）

**整体布局**：左侧简历列表（175px）+ 中间聊天区（flex:1）+ 右侧预览（195px）

#### 左侧面板

- 顶部：产品 Logo
- 简历列表：当前用户所有简历，按最后编辑时间排序，当前简历高亮
- 点击切换简历：整个编辑器刷新（对话历史 + 简历预览同步切换）
- 底部两个按钮：
  - 「⎘ 复制当前简历」→ 弹出确认框（预填名称「xxx (副本)」，可修改）→ 跳转新简历
  - 「+ 新建简历」→ 打开新建弹窗

#### 中间聊天区

**顶部快捷栏**（两行，可用时展示）：

第一行 — 职位描述输入：
- 标签：「粘贴职位描述」
- 多行文本框（高度约 2 行）
- 「开始优化」按钮
- 点击后系统自动构造消息：「我想针对这个职位优化简历：\n\n{JD内容}」发送给 Agent

第二行 — 简历文件上传：
- 「📤 上传简历文件」按钮
- 说明：「PDF / DOCX · AI 智能解析合并」
- 点击后系统自动构造消息：「我上传了一份已有简历，请帮我解析并更新当前内容」发送给 Agent

**对话头部**：
- 简历标题（可点击 inline 编辑改名，失焦自动保存）
- 状态 badge（进行中 / 空闲）

**消息区**：
- 支持 Markdown 渲染
- Agent 工具调用时显示「⚙ 调用 {工具名}…」指示器
- 余额不足时，AI 回复「积分不足，本次请求未能处理」

**底部输入栏**：
- 正常状态：文本输入框 + 发送按钮
- 余额为 0：替换为「🚫 积分已用完，无法发送消息」+ 「充值积分 →」按钮

#### 右侧预览区

- 顶部：「简历预览」标题 + 「换模板」链接
- 主体：A4 等比实时预览，Agent 修改简历后自动刷新
- 底部操作栏：「模板」按钮 + 「导出 PDF」按钮

**模板切换**：
- 点击「换模板」或「模板」按钮 → 右侧滑出模板选择面板（不遮挡聊天区）
- 面板内展示模板缩略图 + 标签，点击即时预览切换
- 关闭面板或点击其他区域收起

#### 上传简历冲突处理逻辑

Agent 解析上传文件后，与当前简历数据对比关键字段（姓名、性别、主要工作经历、学历）：

| 场景 | 处理方式 |
|---|---|
| 冲突少（同一个人，部分字段更新）| 自动智能合并，AI 告知用户改了哪些内容 |
| 冲突多（核心字段差异显著，疑似不同人）| AI 列出具体冲突点，提供两个选项：智能合并 / 用上传内容完全替换 |

### 4.4 账单页（/billing）

**布局**：左侧导航 sidebar + 右侧主内容

**左侧导航**：积分总览 / 使用明细 / 充值记录 / 账号设置

**积分总览页**（默认展示）：

1. **总览卡片组**（2列）：
   - 主卡（渐变紫色）：当前余额（积分）+ 换算金额 + 充值按钮
   - 副卡 x3：本月消耗 / 累计充值 / 今日消耗

2. **30 天用量折线图**：按天展示积分消耗，今日高亮

3. **按简历用量**（本月）：
   - 每行：简历名称 + 进度条 + 积分数 + 换算金额
   - 按消耗从多到少排序

4. **近期流水**（最近 10 条）：
   - 每条：操作图标 + 描述（操作类型 + 关联简历名）+ 时间 + 积分变动（正负）+ 变动后余额
   - 「查看全部 →」链接

## 五、积分与计费

### 换算标准

| 换算关系 | 值 |
|---|---|
| 1000 积分 | = ¥10 |
| 1 积分 | = ¥0.01 |
| 最低充值 | ¥5（500 积分）|
| 新用户赠送 | 100 积分（≈ ¥1），6 个月有效期 |
| 购买积分 | 永久有效 |

### 充值套餐

| 金额 | 积分 | 优惠 | 单价 |
|---|---|---|---|
| ¥5 | 500 | — | ¥0.01/积分 |
| ¥10 | 1000 | — | ¥0.01/积分 |
| ¥30 | 3300 | +10% | ¥0.009/积分 |
| ¥50 | 5500 | +10% | ¥0.009/积分 |
| ¥100 | 12000 | +20% | ¥0.008/积分 |
| 自定义 | 按比例 | — | — |

支付方式：微信支付 / 支付宝（支付接入为独立模块，后续迭代实现）

### 余额状态与触发阈值

| 状态 | 触发条件 | 表现 |
|---|---|---|
| 正常 | 余额 ≥ 50 积分 | 导航栏蓝色积分 chip |
| 偏低警告 | 余额 < 50 积分 | 导航栏黄色警告 chip + 顶部 banner |
| 耗尽 | 余额 = 0 | 红色 chip + 红色 banner + 编辑器输入框替换为充值引导 |

### 余额校验规则

- 后端每次 Chat 请求前校验余额，不足返回 HTTP 402
- **前端不做余额判断**，仅负责展示引导 UI
- 余额扣减为原子操作（数据库层保证，防并发超扣）

### 积分展示颗粒度

| 层级 | 内容 | 查看位置 |
|---|---|---|
| 账户级 | 总余额、本月消耗、累计充值 | 导航栏 chip + 账单页总览 |
| 简历级 | 每份简历本月消耗积分 | 账单页「按简历用量」 |
| 操作级 | 每次操作（JD分析/对话/解析）消耗积分 | 账单页「近期流水」 |
| 消息级 | 单条消息 token 消耗 | 不展示（内部记录用于成本核算） |

## 六、用户流程

### 流程 1：新用户从零建立第一份简历
注册登录 → Dashboard 空状态 → 新建简历（填名称 + 选模板 + 选「从头开始」）→ 进编辑器 → AI 引导对话 → 简历完成 → 导出 PDF

### 流程 2：新用户上传已有简历
新建简历（选「上传已有简历」）→ 进编辑器 → 上传文件 → Agent 解析填充 → AI 报告解析结果 → 继续优化

### 流程 3：老用户继续上次对话
登录 → Dashboard 点击简历卡片 → 编辑器自动加载该简历及其完整对话历史 → 继续

### 流程 4：针对新 JD 优化，保留原版本
进入某份简历 → 「⎘ 复制当前简历」→ 新建副本（输入名称）→ 跳转副本编辑器 → 在顶部粘贴 JD → Agent 分析并优化 → 原版本不受影响

### 流程 5：在编辑器内上传新简历文件（冲突处理）
编辑器顶部「📤 上传简历文件」→ 选择文件 → Agent 解析并检测冲突 → 冲突少：自动合并并告知；冲突多：展示差异，用户选择合并或替换

### 流程 6：创建第二份不同方向的简历
Dashboard「+ 新建简历」→ 填名称 + 选不同模板 → 进编辑器 → AI 长期记忆跨简历共享，无需重新介绍背景

## 七、设计决策记录

记录所有已拍板的设计选择，便于日后追溯。

| 决策点 | 选择 | 原因 |
|---|---|---|
| Resume 与 Session 关系 | 分表存储，业务 1:1，架构预留 1:N | 职责分离，未来可扩展 |
| 多对话方案 | 不做多 Session，用「复制简历」替代 | 消除跨 Session 上下文断裂问题，用户心智更简单 |
| 长期记忆归属 | 用户级，跨简历共享 | 「AI 记得你」是核心价值，不能每份简历重来 |
| 简历命名 | 创建时用户手动命名（必填） | 用户明确命名，避免混淆 |
| 模板切换交互 | 右侧滑入面板 | 不打断对话节奏，即时预览 |
| 模板标签 | UX 筛选用途，不影响数据结构 | 帮助用户发现合适模板，实现简单 |
| JD 粘贴 / 文件上传触发方式 | 系统自动构造消息发给 Agent | 对话历史完整，无黑盒操作 |
| 上传冲突处理 | 冲突少自动合并；冲突多让用户选 | 减少决策负担，同时保证数据安全 |
| 计费模型 | 预充值积分制，为后续订阅套餐预留 | 中国用户心智成熟，低门槛体验 |
| 余额校验位置 | 后端强校验，前端不做判断 | 安全原则，防绕过 |
| 支付接入 | 后续独立模块实现 | 当前阶段充值按钮显示「即将开放」|
| 积分次数估算 | 充值套餐不显示「约 X 次对话」 | 实际消耗差异大，显示会产生误导 |
